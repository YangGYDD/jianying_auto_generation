# 离线输出与实验性剪映接入

## 默认离线输出

离线输出适配器为每条新闻产生以下三个文件。通过 CLI 运行时，每条新闻目录还包含保存后回读核验的 `texts.json` 文案映射；批次根目录另含 `manifest.json`，记录文章、输出类型、验证边界和文件 SHA256。

| 文件 | 用途 | 验证边界 |
| --- | --- | --- |
| `draft.json` | 项目自有的可移植文字、槽位和时间描述 | 写入后完整回读并与预期数据比较 |
| `preview.html` | 可双击打开的独立预览，时间轴展示当时可见的文字；右侧列出全部片段 | HTML 转义；没有远程脚本、字体、图片或接口；保存后回读 |
| `captions.srt` | 所有明确带有 `sequence` 的槽位，按开始时间和 `order` 排序 | 使用槽位毫秒时间；保存后回读 |

离线预览不是视频，也不是剪映草稿。画面使用本项目原创 CSS 视觉，不复现剪映的文字尺寸、动画、布局、转场或渲染。播放按钮演示时间与文字关系。浏览器禁用脚本时仍能阅读完整片段清单。模板的 `width`、`height` 保存在 JSON 中；网页预览统一使用竖屏示意框，不据此验证不同画幅的实际排版。

只有声明为 `sequence` 的片段进入 SRT，固定品牌名和普通标题不会被自动当作字幕；没有序列时 SRT 为空文件。同一序列必须连续、同轨且按段递增。多个序列可以来自不同轨道，SRT 会把它们合并到一个文件；如果时间重叠，字幕播放器可能重叠显示。需要单一连续字幕时，只为一条字幕轨道声明序列。

## 实验性明文剪映适配器

本适配器是独立实现，未包含旧项目的剪映 SDK、加解密实现、业务模板或媒体。它只处理用户自己提供且有权使用的明文 `draft_content.json`，不调用剪映、不寻找已安装草稿目录、不操作剪映界面，也不解密文件。

先按 README 安装，再复制可编辑的原创示例输入。`local` 必须是尚不存在的目录；如果已经初始化，直接使用已有文件即可：

```powershell
nvbatch init --directory local
```

准备自己的剪映模板目录及槽位映射后运行：

```powershell
nvbatch run --news local/news.json --template my-slots.json --output outputs/jianying-check --export jianying --jianying-template my-template
```

`my-template` 和 `my-slots.json` 由用户准备，仓库不含已适配真实剪映版本的业务模板。可参考初始化生成的 `local/template.json` 的槽位字段，但必须根据自己的草稿逐段重新映射轨道、片段和时间，不能把离线模板当作真实剪映模板直接使用。请用自己的新闻内容替换 `local/news.json` 中的示例新闻；离线示例里的 `demo_texts` 也是绑定示例槽位的固定映射，接入新槽位时应删除该字段使用离线抽取，或按新槽位显式更新。槽位不能表达文案时，会按长度、用途等规则拒绝生成，不会静默截断。

接入步骤：

1. 准备一份与正在编辑的项目隔离的模板副本，确保拥有其中字体和媒体的使用权。源目录在处理时保持不变，不从正在编辑的项目边编辑边复制。
2. 确认 `draft_content.json` 能被 UTF-8 JSON 解析，并符合下方受限结构。加密、复合文字、花字或关键帧模板不能通过改文件扩展名转换成支持格式。
3. 把所需媒体和字体放在模板副本中，将其 JSON 引用调整为模板目录内的相对路径，例如 `assets/background.png`。拒绝绝对路径、网络地址、`..`、软链接和 Windows 目录联接。不会自动迁移外部素材。
4. 建立 `my-slots.json`：对每个文字片段分配独立槽位，填写固定/生成模式、用途、重复许可、字数行数和顺序。`track` 是按 `type=text` 筛选后的轨道索引，从 0 开始；`segment` 是该文字轨道中的片段索引，从 0 开始。
5. 槽位 `start_ms × 1000`、`duration_ms × 1000` 必须等于原草稿 `target_timerange.start`、`duration`。非整毫秒时间不能由当前槽位协议精确表示，因此会拒绝。适配器保留原时间，不能拉伸时间轴。
6. 运行命令，查看批次清单和输出。输出是独立工作目录中的结构验证结果，不会注册进剪映草稿列表。
7. 如要用于真实剪映，请在自己可恢复的独立试验项目中，按所用版本实际支持的导入/替换流程手工验证。检查全部文字、字体、换行、媒体、时长、预览和导出。通过后再决定是否用于生产。

### 当前明确接受的范围

- 顶层具有 `tracks` 数组、`materials` 对象和 `materials.texts` 数组。
- 轨道类型限 `text`、`video`、`audio`；复合文字和嵌套草稿不支持。
- 每个文字片段通过 `material_id` 对应唯一可解析的文字材料；所有文字片段必须恰好有一个槽位，不能只替换前几个片段。
- 文字材料 `content` 是 JSON 字符串，内部只允许 `text` 和可选 `styles`。
- 如果出现 `styles`，必须是只有一项的数组，其 `range` 恰好覆盖原文字全文；空数组、多段样式和局部范围均拒绝。当前实现采用 UTF-16 单元长度，包括换行和非 BMP 字符；这是本适配器支持的格式约定，不代表所有剪映版本都采用此约定。
- 单一样式仅允许 `range`、`font`、`size`、`fill`、`bold`、`italic`、`underline`、`strikethrough`、`stroke`、`shadow`、`color`、`letter_spacing`。保留已支持样式属性，将全文范围更新为新文字长度。复杂样式、文字关键帧、语音对齐、链接语音和附加材料引用均拒绝。
- 每段独立复制文字材料并分配新材料 ID。即使原来多段共用一个材料，也分别写入各自槽位的文字。旧文字材料从输出文字材料列表移除，不让未引用的原始正文残留。
- 支持的素材扩展名是 PNG、JPG/JPEG、WebP、BMP、MP4、MOV、M4V、WAV、MP3、M4A、AAC、OGG、TTF、OTF。这里只校验文件存在、路径范围、大小和复制前后字节一致，不验证媒体解码能力和字体许可。

### 复制和安全边界

采用选择性克隆：复制改写后的 `draft_content.json` 以及其中 `path` / `*_path` 字段引用的本地媒体或字体。嵌在文字 `content` 中的字体路径也会检查。不会把整个模板目录原样复制，旁边的配置、草稿历史和 `draft_meta_info.json` 不会自动进入结果。原草稿 JSON 中受支持的其他属性按原值保留；这不是针对用户自备草稿内容的脱敏器，真实业务输出仍应按私密资料管理。

JSON 文件上限 20 MiB，单个素材上限 256 MiB，素材合计上限 512 MiB。只接收已存在的空输出目录，拒绝覆盖现有文件，拒绝模板与输出相互包含，拒绝经过链接或重解析点的目录，并拒绝写入名称为 `JianyingPro`、`CapCut` 或 `com.lveditor.draft` 的目录树。CLI 在整个批次成功后才发布最终输出目录。

这些约束是当前小范围适配边界。遇到不支持格式会失败并解释，不尝试猜测字段、自动移除关键帧、解密或强行产出一个看似成功的草稿。

### 验证究竟证明什么

成功表示：保存后的 JSON 与预期完全一致；每个文字片段的内容正确、材料独立、原时间未改；样式范围符合本适配器约定；已复制素材字节一致。`verified: true` 仅表达此结构和保存回读验证。返回的 `verification_scope` 也明确标记编辑器 GUI 未验证。

自动化测试使用本项目原创的极小合成 JSON，覆盖同轨多段共享材料、前后文不同、连续字幕、UTF-16 范围、保存损坏、HTML 转义、路径逃逸及覆盖保护。合成测试通过不等于真实剪映兼容验收。

本次 HTML 预览的人工浏览验收受到自动化浏览器的本地文件访问安全策略阻止，未绕过限制。因此已核验 HTML 的生成、转义和保存回读，但尚未完成实际浏览器中的布局与播放交互验收。用户可在自己的浏览器中打开输出文件检查。

当前没有经过本项目端到端 GUI 验证的剪映版本，也不承诺草稿能直接出现在某版本的草稿列表中或成功导出视频。安装版本、加密状态、缺失字体、草稿索引/元数据、在线特效、媒体解码及实际排版都需要在目标 Windows 电脑单独验证。Linux CI 仅验证标准库逻辑，不代表剪映支持 Linux。

## 常见失败

| 提示或现象 | 处理办法 |
| --- | --- |
| 无法读取明文 JSON | 检查文件名、编码和实际结构；加密草稿不在支持范围内 |
| 槽位未完整覆盖 | 逐条枚举所有文字轨道和片段，每段一个槽位 |
| 时间不匹配 | 对照源文件的微秒时间填写毫秒值；不要自行取整 |
| 多段样式或附加材料不支持 | 使用独立试验副本创建简单文本模板，或等待针对该格式的专项适配 |
| 绝对路径或外部依赖被拒绝 | 将有权使用的素材放进模板副本，显式改为相对路径 |
| 输出目录已存在 | 使用新的输出目录；程序不会覆盖此前批次 |
| JSON 校验通过但剪映打不开 | 仍属未通过目标版本 GUI 验收；保留去敏后的最小复现，按问题模板报告，不将此批次当作成片交付 |
